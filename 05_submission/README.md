# Submission package

Everything here is regenerated by `python MAIN.py` from the supplied parquet
files. No number in the deck is typed in: the slide builder reads these CSVs at
build time and fails loudly if a metric it wants is missing, which is why the
deck cannot disagree with the backtest that produced it.

## The four items the rules ask for

| Rule | File |
|---|---|
| 1. Deck with appendix, one PDF | `FIAM_deck.pdf` (8 pages + 5 appendix; source `FIAM_deck.pptx`) |
| 2. Monthly holdings | `holdings.csv` |
| 2. Portfolio return series | `portfolio_returns.csv` (monthly), `daily_returns.csv` (daily) |
| 3. Code | `../MAIN.py` |
| 4. Licence | `../LICENSE` |
| 5. CVs | supplied separately by each team member |

## Conventions, stated so nothing has to be inferred

**Returns are GROSS of trading costs** wherever they are not labelled
otherwise. `portfolio_returns.csv` is gross, and it is the series behind the
deck's headline information ratio. Costs are applied as a sensitivity rather
than baked in, because the right assumption is a judgement and burying it in
the base case hides it: `deck_pack.csv` carries the information ratio at 0, 10,
20, 30 and 50 bps per unit traded, and the deck reports both the gross number
and the 20bps number side by side on page 1.

**Weights are fractions of NAV.** They sum to 2.00 in absolute value (200%
gross, the limit the rules set) and to about +0.125 net. Positive is long,
negative is short. Short proceeds are held as collateral earning the 3-month
T-bill, which is why the benchmark is cash plus 4% and why the cash leg cancels
out of the active return.

**The hurdle** is the 3-month T-bill plus 4% per year, monthly, from the pinned
FRED snapshot in `01_data/raw/external/`. Active return is the strategy return
minus that hurdle.

**Delisted positions** are marked at 0% in the base case. `deck_pack.csv`
carries the sensitivity at -30% (Shumway), -50% and -100%; the appendix
explains why -30% is a conservative stress here rather than a likely case.

## Column reference

`portfolio_returns.csv` — one row per holding month.

| Column | Meaning |
|---|---|
| `target_month` | the month held, YYYY-MM |
| `total` | strategy return, gross of costs (cash + spread) |
| `spread` | the long/short spread alone |
| `long_leg`, `short_leg` | each leg's contribution |
| `hurdle` | 3M T-bill + 4%/yr, monthly |
| `active` | `total` - `hurdle`, the series behind the information ratio |
| `sp500_ret`, `cash_monthly` | context series |

`holdings.csv` — `DATE`, `PERMNO`, `TICKER`, `COMPANY_NAME`, `WEIGHT`, one row
per position per month, 13,600 rows over 68 months.

## Checking the deck against itself

    node 05_submission/build_deck.js
    python 05_submission/audit_deck.py

`audit_deck.py` exists because two numbers on these slides went stale without
anything failing: the leg attribution stayed as four literals after the book
that produced them was replaced, and a patch that claimed to add two bullets to
page 3 matched nothing and reported success. It runs two passes -- every
result-shaped number typed into the slide source must be listed with a reason,
and every value in the CSVs is looked for in the text extracted back out of the
built PDF. The second pass is the one that matters: a patch matching nothing
still succeeds, but a number missing from the PDF does not.

## Supporting exhibits

`deck_pack.csv` and `robustness.csv` hold the performance pack and the six
robustness tests. `leg_attribution.csv`, `neutrality_check.csv`,
`sector_dose.csv`, `exp_sector_*.csv` and `exp_refresh.csv` hold the
diagnostics the appendix reports, including the ones whose conclusions we
withdrew. `feature_importance.csv` is the model's own split gain over six
annual refits.
